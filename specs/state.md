# State & Data Model

This file owns Synthia's canonical vocabulary. Every persisted concept is defined here
once; `api.md` and `agent.md` reference these names rather than redefining them.

State lives in four places: **Postgres** (relational + pgvector), a **semantic-memory
store** managed by mem0, the **filesystem** (attachments/uploads), and **ADK-managed**
session/event tables.

## Core vocabulary

- **Thread** — a user-facing chat conversation. Identified by a `bigint` id generated
  client-side as `String(Date.now())`. May link to at most one **project**.
- **Message** — one turn within a thread (user or assistant).
- **Task** — a unit of heavy work the front agent delegates to the task agent. Id has the
  form `task-<uuid>`. May run synchronously (foreground) or in the background.
- **Session** — an ADK agent session. Its id equals the `thread_id` for chat sessions or
  the `task-<uuid>` for task sessions.
- **Conversation** — an episodic-memory record: a summarized, embedded transcript of a
  completed run, used for semantic recall of past conversations.
- **Project** — a user-facing workspace holding a markdown document, ordered sections, and
  media attachments.

## Postgres tables (owned by Synthia migrations)

### thread_sessions
Maps a chat thread to its backing ADK session id.
- `thread_id` BIGINT PRIMARY KEY
- `session_id` TEXT NOT NULL

### threads
User-facing chat threads.
- `id` BIGINT PRIMARY KEY
- `title` TEXT NOT NULL
- `project_id` UUID NULL → `projects(id)` ON DELETE SET NULL
- `created_at`, `updated_at` TIMESTAMPTZ DEFAULT NOW()
- Unique index on `project_id` WHERE NOT NULL — a project links to at most one thread.

### messages
Chat history within a thread.
- `id` UUID PK DEFAULT gen_random_uuid()
- `thread_id` BIGINT NOT NULL → `threads(id)` ON DELETE CASCADE
- `role` TEXT NOT NULL (`user`, `assistant`)
- `message_type` TEXT NOT NULL (`user`, `result`, `thought`, `progress`, `image`)
- `content` TEXT NOT NULL
- `metadata` JSONB NULL
- `created_at` TIMESTAMPTZ DEFAULT NOW()
- Index on `(thread_id, created_at)`.

The `metadata` JSONB may carry: `attachments` (array of
`{name, content_type, file, path}`), `persona`, `consulted_personas`, `reaction`,
`cost_usd`, `success`, and `voice` (true for turns spoken in voice mode, see `agent.md`). Attachment files live on the filesystem (see below); there is no
FK from metadata to the files.

### tasks
Heavy task-agent runs delegated from the front agent.
- `id` TEXT PK (`task-<uuid>`)
- `thread_id` BIGINT NULL
- `label`, `request`, `result` TEXT NULL (result truncated per env config, ~50K chars)
- `status` TEXT NOT NULL — `queued`, `running`, `done`, `error` (not enforced by a check
  constraint). The system shall transition a task queued → running → done|error.
- `background` BOOLEAN NOT NULL DEFAULT FALSE — true = async dispatch, false = sync delegate.
- A voice-mode `browse` (see `agent.md`, "Browser agent") also creates a row here with
  `background = true` and a label starting with `Browse:`; no other schema difference.
- `created_at`, `updated_at` TIMESTAMPTZ DEFAULT NOW()
- Indexes on `updated_at DESC` and `(thread_id, updated_at DESC)`.

### projects
- `id` UUID PK DEFAULT gen_random_uuid()
- `name` TEXT NOT NULL
- `status` TEXT NOT NULL DEFAULT `active` (`active`, `closed`)
- `document` TEXT NOT NULL DEFAULT '' (markdown)
- `next_step` TEXT NOT NULL DEFAULT '' (short ~5–10 word action)
- `sections` JSONB NOT NULL DEFAULT '[]' — array of `{id, title, body, order}`
- `media` JSONB NOT NULL DEFAULT '[]' — array of
  `{id, name, content_type, file (path), caption, order}`
- `created_at`, `updated_at` TIMESTAMPTZ DEFAULT NOW()
- Indexes on `(status, created_at DESC)` and `created_at DESC`.
- Sections and media are returned to the API sorted by their `order` field.

### conversations (episodic memory)
A summarized, embedded transcript of a completed run.
- `id` UUID PK DEFAULT gen_random_uuid()
- `transcript` TEXT NOT NULL
- `summary` TEXT NOT NULL
- `embedding` VECTOR(384) NULL
- `thread_id` BIGINT NULL — optional link back to the originating thread
- `created_at` TIMESTAMPTZ DEFAULT NOW()
- Indexes: IVFFLAT `vector_cosine_ops` (lists=100) on `embedding`; `created_at DESC`; GIN
  full-text on `to_tsvector('english', summary || ' ' || transcript)`.

When a run completes, the system shall summarize the transcript and store a conversation
row with an embedding generated by `all-MiniLM-L6-v2` (384-dim) over the summary plus the
first ~4000 chars of transcript.

### job_executions (skill/job ledger)
Telemetry ledger for skill and scheduled-job runs; drives skill optimization and rollback.
- `id` UUID PK DEFAULT gen_random_uuid()
- `job_name` TEXT NULL
- `skill_names` TEXT[] NOT NULL DEFAULT '{}'
- `thread_id` BIGINT NULL
- `success` BOOLEAN NOT NULL
- `error` TEXT NULL
- `cost_usd`, `duration_s` NUMERIC NULL
- `tool_call_count` INTEGER NOT NULL DEFAULT 0
- `skill_versions` JSONB NOT NULL DEFAULT '{}' (skill name → version tag)
- `created_at` TIMESTAMPTZ DEFAULT NOW()
- Indexes: `(job_name, created_at DESC)`; GIN on `skill_names`; `created_at DESC`.

### push_subscriptions
Browser Web Push subscriptions (see `api.md` for the VAPID flow).
- `endpoint` TEXT PRIMARY KEY
- `keys_p256dh` TEXT NOT NULL
- `keys_auth` TEXT NOT NULL
- `created_at` TIMESTAMPTZ DEFAULT NOW()
- Subscribe is an upsert on `endpoint`. The system shall delete a subscription when a send
  returns 403/404/410.

## Vector stores

| Store | Where | Embedding model | Dims | Written by | Purpose |
| --- | --- | --- | --- | --- | --- |
| Episodic | `conversations.embedding` | all-MiniLM-L6-v2 | 384 | episodic memory service (on run completion) | recall of past conversations |
| Semantic | mem0-managed pgvector tables | nomic-embed-text via Ollama | 768 | the `add_memory` tool | durable facts/preferences about the user |

Semantic memory (mem0) manages its own pgvector tables; Synthia migrations do not create
them. All semantic memories are tagged `user_id="default"`. Migration 005 moved semantic
embeddings from OpenAI (1536-dim) to Ollama nomic-embed-text (768-dim) and left a
`mem0_backup` table behind.

## Filesystem state

- **Uploads / attachments:** `{cwd}/uploads/{thread_id}/`. User uploads and
  agent-generated images are saved here per thread, filenames sanitized and
  de-duplicated (`{stem}_{counter}{suffix}`), with path-traversal protection. Referenced
  from `messages.metadata.attachments[]` and `projects.media[]`; served via the attachment
  endpoint in `api.md`. No FK; the filesystem is the source of truth for bytes.
- **Skills:** built-in skills under the repo `skills/` dir; user skills under
  `~/.claude/skills/`. Skill version snapshots/ledger are managed by the skill-version
  tooling (see `agent.md`).

## ADK-managed state (sessions & events)

The Google ADK owns these tables via `DatabaseSessionService` (Postgres,
`postgresql+psycopg://`). Synthia reads them but does not migrate them.

- **sessions** — `id` (= thread_id or `task-<uuid>`), `app_name` (always `synthia`),
  `state` JSONB (opaque to Synthia), `update_time`.
- **events** — `session_id`, `timestamp`, `event_data` JSONB holding
  `content.parts[].{text, function_call, function_response}`, `usage_metadata`,
  `finish_reason`, `error_message`.
  Voice-mode turns append transcription events (text parts authored `user` / `model`);
  audio blobs are never stored.

## Relationships (summary)

```
threads (1)──(1) thread_sessions ──(session_id)── ADK sessions ──(N)── events
   ├─(N) messages ──(metadata.attachments)──▶ filesystem uploads/{thread_id}/
   ├─(N) tasks (by thread_id)
   ├─(0..1) projects (threads.project_id, unique) ──▶ sections[], media[]──▶ filesystem
   └─(N) conversations (episodic, by thread_id, optional)
job_executions ──(optional thread_id, skill_names[])
mem0 semantic memories (external pgvector, user_id="default")
```

## Open questions

1. **Project↔thread cardinality.** The unique index on `threads.project_id` enforces one
   thread per project, but project/thread linking code reads as if it could be looser.
   Confirm the intended cardinality and state it as a single rule here.
2. **Task status check constraint.** `status` values are convention-only; no DB check
   constraint. Decide whether to enforce the enum.
3. **`mem0_backup` lifecycle.** Migration 005's backup table is never cleaned up. Decide
   whether it should be dropped.
4. **ADK `sessions.state` shape.** Treated as opaque. If Synthia ever depends on its
   internals, document the shape here.
